Which block should the robot touch?

A robot sees a color cue and must touch the matching block after the cue disappears. When it’s time to move, the table looks the same whether the cue was green or blue.

Existing memory-augmented vision-language-action (VLA) models can keep reaching for the same block or switch to the wrong one. We call this gap between the supplied history and the chosen action memory–action misalignment.

The three components of MemAlign

MemAlign teaches the robot to use a remembered cue to reach for the right block.

  1. Counterfactual supervision

    During training, we show the correct reach for each earlier cue while keeping the current scene, instruction, and starting pose fixed.

  2. History-aware low-rank modulation

    When the robot acts, a small controller uses its memory to adjust the action network. A different remembered cue can steer the reach to a different block.

  3. Visual rebinding (optional)

    In tasks such as RememberColor, the robot matches the remembered visual cue to the current camera view. It uses the block’s estimated position to refine the reach.

Matched ablation and inference cost

In the matched ShellGameTouch ablation, the full method completes the correct target under both histories in 84.67% of scenes. With visual rebinding fixed, this drops to 2.67% when history-aware modulation is removed and to 52.00% when counterfactual supervision is removed.

On an NVIDIA L40, MemAlign adds approximately 11% latency per 16-step query and 0.8 GiB of peak allocated GPU memory in the RC5 and ShellGameTouch profiling runs.
